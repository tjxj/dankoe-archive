先说做出来的是什么

Dan Koe 的 19 个长视频(合计 11.1 小时、135,592 个英文词),被拆成了一个四层结构的学习档案站:

  1. 封面与原片入口:官方封面卡 + YouTube 官方嵌入播放器(不搬运视频文件);
  2. 中英对照稿:逐句对齐,点任意一句,播放器跳到那一秒,字幕列表跟随播放滚动;
  3. 英文原稿 / 中文译稿:去掉时间断行、可以连续阅读的长文,段首时间标记同样可点;
  4. 图文总结:核心主张、主线卡片、知识点、时间线、原话摘录、行动清单——每一条都绑到视频里的真实画面或真实时间点,点图、点时间戳,直接跳回原片那一刻。

第四层是重点,也是这篇文章想讲清楚的部分。做不到"指回原片",总结就只是又一篇读后感。

整条流水线已经开源,Python + 纯静态站,没有后端、没有前端构建链。下面把实现过程、踩过的坑、以及你换成自己喜欢的频道需要改什么,一次说完。

几个值得抄走的决定

1. 有字幕就翻译,不转录——但先用数据确认"有字幕"是真的

YouTube 自动字幕经常缺尾段、缺整段。所以在决定"跳过 ASR"之前,先量化校验每一条字幕:内部空洞数、尾部缺口、语速(词/分钟)三项指标,全部落在合理区间才允许走翻译路径,否则自动回退到转录。实测这 19 条:内部空洞 0 处,最差尾部缺口 0.8 秒(全长 1862 秒),语速 182–216 词/分——这才敢不转录。阈值是代码里的常量,不是口头约定;新视频进来自动过同一道检查。

2. 对齐比生成重要:让每一句话都有坐标

  • 译文对齐:翻译走"编号行协议"——输入第 N 行,模型必须输出 N 译文。解析器有严格/宽松两套,宽松模式只接受"编号恰好等于期望值"的裸行,防止模型把译文里的数字(比如 "5 skills")误当成行号把整批错位。这个行为有单元测试锁着。
  • 摘录对齐:提示词要求 quote 逐字摘自字幕,渲染时三级回退定位:整句互相包含 → 开头 5 词锚 → 结尾 5 词锚;三级都失败就不显示时间戳——宁缺勿错。实测 92/92 条摘录全部定位成功,抽验 12/12 逐字命中字幕。
  • 时间线对齐:模型给的秒数是"印象中的秒数",渲染时统一 snap 到最近真实句首,保证"显示的时间 = 点过去的时间"。

3. 纯静态站:0 后端、0 构建链、0 托管费

Jinja2 模板直接吐出 HTML,交互用原生 JS(页签、跟随滚动、跳转、复制原文+链接),样式一个 CSS 文件。托管在 Cloudflare 的静态资产上,绑了个次级域名。播放器一律 YouTube 官方嵌入——视频版权是别人的,站里一个视频字节都不放,只放自己的译文和总结。

4. LLM 工程化的三个细节

  • 磁盘缓存:每次调用的指纹(模型+参数+prompt+输入哈希)落盘,重跑不花重复的钱;
  • 重试要认网络错误:只重试 429/5xx 是不够的,requests.Timeout、ConnectionError 同样要进重试队列——这是我第一次 smoke test 挂着之后修的;
  • 超时是给思考留的:合成阶段开着 thinking 还要吐 16k token 的 JSON,默认 300s 不够,实测超时一次后调到 900s。超时参数不进缓存指纹,改超时不会废掉已有缓存。

5. 给"诚实"留一个槽位

总结里有置信度标签(高/中/待核验),还有一个"局限与待核验"章节,由模型自己声明:哪条是低置信推断、哪段其实是广告口播、哪个画面编号是猜的。让模型交代自己不确定的地方,比让它假装全知有用得多。

坑日志:对做同类项目的人最值钱的部分

  1. CSS aspect-ratio 会输给 HTML 的 height="405" 属性。属性是表现层提示,作者 CSS 不写 height 就赢不过它,16:9 的帧图被撑成竖图。修:凡是模板上写了 width/height 的 <img>,CSS 必须显式 height: auto。
  2. 作者样式的 display 会赢过 UA 的 [hidden]{display:none}。我给"播放器加载失败"的降级罩写了 display:grid,忘了补 [hidden]{display:none},结果罩子从首字节起永远盖在播放器上——更阴的是它把"播放器其实是好的"也一起盖住了,截图里只以为是无头环境加载失败。修:补 [hidden] 规则,并给验收加 computed-style 探针。
  3. 无头 Chrome 会在加载后期补发一次 prefers-color-scheme 的 change 事件。"跟随系统"监听器把 ?theme=dark 强制主题抢了回去,整页变浅,而所有 DOM 断言全绿。修:change 回调跳过强制态;验收加 PNG 像素级断言(解导航栏底色点),暗色才算真的验过。
  4. 模型把列表字段返回成一整串字符串时,Jinja 会逐字迭代。某个视频的 caveats 是 str,页面上排成一列竖字,页面虚高 8000px。修:渲染层按行拆 + 写入时规整 + 回归测试,三层。
  5. --virtual-time-budget 会在子帧网络请求挂起时停表:8 秒兜底定时器在截图窗口里可能根本没跑,你看到的 DOM 是"更早"的状态。修:判断定时器有没有执行,不能靠截图里的文案。

这五条有一个共同点:自动化断言全绿,页面其实是坏的。所以验收必须是"断言 + 像素 + 人眼"三层:37 个单元测试锁回归,无头 Chrome 跑 108 项断言(HTTP 全 200、DOM 关键节点、console 过滤后零报错、computed style 探针、暗色像素),再对四档视口 + 暗色的截图逐张人眼看——自动化证明没崩,眼睛证明好看。线上部署完,同一套验收对着真实 URL 再跑一遍。

做一个你自己喜欢的版本

仓库里是完整可跑的流水线,换频道只需要改配置:

git clone https://github.com/tjxj/dankoe-archive && cd dankoe-archive
pip install jinja2 requests              # 第三方依赖就这两个(SRT 解析是自己写的)

export OPENAI_API_KEY=...                # 任何 OpenAI 兼容接口都行
# config.json 里换模型:翻译/合成用一个强推理模型,视觉用一个 VL 模型

# 1) 用 yt-dlp 把目标频道的视频和英文字幕下下来(版本要新,老版本会 403)
# 2) 跑全链:校验 → 重组 → 翻译 → 抽帧 → 视觉 → 合成 → 建站
python3 run.py all
# 3) 本地看一眼,然后部署
python3 run.py serve                     # http://127.0.0.1:8765/
wrangler deploy                          # Cloudflare 静态资产,免费额度很大

config.json 里能改的:模型名、并发、超时、抽帧密度、总结的详细程度。提示词在 pipeline/summarize.py 顶部,想加"逐章笔记""金句卡片""术语表"之类的层,照着自己加一个 section 即可——模板和渲染层都是按"总结里有什么就渲染什么"设计的,缺数据会自动降级成提示,不会崩。

成本参考:19 个视频、11.1 小时素材,视觉 + 合成合计约 72.5 万 token(SiliconFlow 计价),一次性;之后每加一个视频只花它自己那一份。翻译和合成都有磁盘缓存,改模板不花钱,改提示词只重跑合成。

如果你也用 Claude Code,还有个更细的入口:我技能库里的三个 skill 可以单独使——z-video-downloader 管下载、z-video-study-webpage-qwen 管单个视频的多模态分析、z-web-pack 管把同主题网页打成写作素材包。仓库里的流水线,就是把前两个频道化、工程化之后固化下来的版本;写配套文章时,素材包同样走 z-web-pack。

为什么值得做这件事

AI 没有替我看视频——11 个小时我一分没少看。它做的是让"看过"留下痕迹:三个月后我想起某个论点,能在一秒内跳回他说那句话的那一帧,而不是重新 scrub 二十分钟进度条。

总结谁都会生成,能指回原文的总结才是学习工具,指不回去的只是读后感。这条线,就是这个项目全部的技术含量所在。
